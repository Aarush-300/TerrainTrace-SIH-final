─── PROJECT OVERVIEW ────────────────────────────────────────────────────────────

Name:    TerrainTrace – Landslide Early Warning System
Contest: Smart India Hackathon (SIH-3)
Purpose: Real-time AI-driven landslide risk prediction and visualization for the
         Himalayan/Northeast India region. Users click the map or pan/zoom to
         receive live ML-based risk assessments derived from terrain, weather,
         and geology data.
Status:  Functional MVP. All three services run and communicate. Known gaps listed
         under TODOs/Issues below.

─── FRONTEND ARCHITECTURE ───────────────────────────────────────────────────────

Multi-page SPA using React Router v6.

Routing & Layout (App.jsx, NavShell.jsx):
  /gis-dashboard   → Dashboard.jsx (Main Map View)
  /report          → ReportPage.jsx (Landslide Documentation Portal, offline-first)
  /safety          → SafetyPage.jsx (High Risk Areas & Safety Measures)
  /admin/alerts    → AlertDispatchPage.jsx (CAP XML Alert Console)
  /routes          → EmergencyRoutesPage.jsx (OSRM Route Planner)

State (Dashboard.jsx — lifted state for Map/Sidebar):
  landslides, liveRiskPoints, liveLoading, prediction, predictionStatus, 
  predictionError, staleAt, selectedLat/Lng, fieldReports, statsRefreshKey
  NEW: riskHorizon (nowcast/24h/72h), selectedState

Derived (useMemo in Dashboard.jsx):
  corridors, riskAreas

Key data flows:
  1. On mount: getLandslides() → Map renders historical markers
  2. On map pan/zoom: getViewportRisk(bounds, zoom, riskHorizon)
     → liveRiskPoints accumulate → corridors + riskAreas recomputed
  3. On map click: predictRisk(lat,lng) → prediction state → RiskPanel
  4. On report submit (/report): submitReportWithMedia → POST /api/reports. 
     If offline, saves to IndexedDB and registers background sync ('sync-reports').

Components:
  NavShell.jsx      Shared layout wrapper with sidebar and mobile hamburger
  Dashboard.jsx     GIS Dashboard page shell
  Map.jsx           Leaflet map with new overlays (Roads, Assets, Rainfall)
  FilterBar.jsx     Controls for state/district zooming and risk horizon
  ReportPage.jsx    Full-page form with GPS extraction and image compression
  SafetyPage.jsx    Displays active HIGH/CRITICAL zones and safety accordion
  AlertDispatchPage.jsx  Pending reports table + multilingual CAP alert form
  EmergencyRoutesPage.jsx Priority triage table + OSRM route planner map

Map configuration:
  Default center: [22, 88], zoom 5
  Base layers: OpenStreetMap, Esri World Imagery
  Overlays: Landslide Points, Risk Corridors, Risk Areas, Historical Landslides, 
            Citizen Reports, Road Connectivity, Vulnerable Assets, Rainfall Overlay
  LOW/UNKNOWN risk points filtered out before rendering.

─── FEATURE COLLECTION PIPELINE (Node) ──────────────────────────────────────────

feature.service.collectFeatures(location)
  ├── terrain.service.getTerrainFeatures()
  │     → Open-Meteo /v1/elevation (5 sample points, 100m offsets)
  │     → elevation_m, slope_deg (computed from N/S/E/W gradient)
  │     → TTL cache 24h, cache key: lat.toFixed(3),lng.toFixed(3)
  ├── weather.service.getWeatherFeatures()
  │     → Open-Meteo /v1/forecast (past_hours=72, hourly precip + soil moisture)
  │     → rainfall_24h_mm (sum last 24 hourly values)
  │     → rainfall_3d_mm  (sum last 72 hourly values)
  │     → soil_moisture_pct (last known soil_moisture_0_to_7cm × 100)
  │     → TTL cache 10min
  ├── geology.service.getGeologyFeatures()
  │     → Macrostrat /api/v2/geologic_units/map → lithology string
  │     → GEM faults GeoJSON (fetched once, process-level cache) → fault_distance_m
  │     → TTL cache 7 days (lithology)
  └── infrastructure.service — always returns unavailable (stub)

Returns: { features, missingFeatures, requiredMissingFeatures, providerStatus, dataTimestamp }
CatBoost handles NaN natively — prediction proceeds even with missing features.

─── ML/AI PREDICTION FLOW ───────────────────────────────────────────────────────

Node → Python flow (Batch Optimized):
  ml.service.predictBatch(features_list)
    → POST http://localhost:5001/predict_batch  { points: [{features: {...}}, ...] }
    → Python: schemas.validate_features() per point → build_model_frame_batch() 
    → Single predict_proba() call on multi-row DataFrame
    → Response: { results: [{ probability, risk_score, confidence, model_version }, ...] }

Python predictor (predictor.py):
  - Singleton via get_predictor()
  - predict() for single point, predict_batch() for arrays
  - Loads models/active/landslide_model_package.joblib

ML output:
  probability    float [0,1]     P(landslide)
  risk_score     int [0,100]     probability × 100 rounded
  confidence     float           max(p, 1-p)
  model_version  string          from env or feature_schema.json

Risk level thresholds (server/src/config/risk-levels.json):
  LOW      probability ≤ 0.39
  MODERATE probability ≤ 0.59
  HIGH     probability ≤ 0.79
  CRITICAL probability ≤ 1.00

─── GIS / MAP DATA FLOW ─────────────────────────────────────────────────────────

DEM (Digital Elevation Model):
  File: himalayan_cop90_dem.tif (1.6 GB)
  Reader: server/src/utils/demReader.js (getSlope reads 3x3 pixel window)

Viewport batch prediction (viewportController.js):
  - Receives {bounds, zoom, riskHorizon}
  - Computes dynamic step and jitter
  - Reads DEM slope per point, drops slope < 5°
  - Collects regional features once at viewport center
  - Makes ONE predictBatch() call for all uncached points (eliminates N+1 issue)
  - Point cache TTL 10 min (TtlCache)

Client-side derived layers (geoUtils.js):
  buildCorridors: HIGH+CRITICAL chains via graph DFS
  buildRiskAreas: DBSCAN + convex hull for MODERATE+ points

Emergency Routes (OSRM):
  - Origin/Dest → POST /api/routes/find → OSRM public API proxy
  - Post-processes route geojson to flag segments passing near VERIFIED ROAD_BLOCKAGE reports.

─── CONFIGURATIONS & CONVENTIONS ────────────────────────────────────────────────

Feature registry (server/src/config/features.json):
  Single source of truth for which features are collected.
  Each entry: enabled, source (terrain/weather/geology/infrastructure),
  provider_key (key in service result.values), model_key, required_for_prediction.
  Disable a feature by setting "enabled": false — no code change needed.

Risk levels (server/src/config/risk-levels.json):
  Configurable probability thresholds. Order matters; find() returns first match.
  Thresholds: 0.39/0.59/0.79/1.0 for LOW/MODERATE/HIGH/CRITICAL.

Feature schema (python-service/feature_schema.json):
  Owns model_column mapping and categorical coercion rules.
  model_version field sets default version string.

API module convention (client):
  All HTTP calls go through src/api/ modules (riskApi.js, reportsApi.js).
  Never call axios directly from components.

All UI text via src/i18n/en.json — use t.keyName pattern, never hardcode strings.

CSS: single file App.css. No CSS modules. Class names: kebab-case.

MongoDB optional: server starts without DB. All DB-dependent endpoints return
empty/graceful responses when mongoose.connection.readyState !== 1.

Error propagation:
  - MlServiceError → app.js handler → 502/422 with clean JSON
  - Validation errors have .status property set → res.status(error.status)
  - Unhandled → 500

─── KNOWN ISSUES / TODOS / HARDCODED VALUES ────────────────────────────────────

PROXY/HARDCODED:
  - viewportController.js line 84: elevation_m = slope_deg × 100
    This is an explicit fallback proxy, NOT real elevation. The DEM is used for
    slope only; elevation from DEM is not extracted (only slope from 3×3 window).
  - Viewport regional features sampled at viewport CENTER only. Points near
    viewport edges share center's weather/geology, not their own.

CONCURRENCY:
  - viewportController CONCURRENCY=2: deliberately low to avoid Open-Meteo
    rate-limiting bans. Each point still triggers 1 ML call to Python.
    With target 400 points per viewport, this can be slow.

STUB/INCOMPLETE:
  - infrastructure.service.js: always returns unavailable. No road/bridge data.
  - getReports() in reportsApi.js: backend has no GET /api/reports endpoint yet;
    the function silently returns [].
  - POST /api/risk-zones/refresh: returns 202 with no action (intentional stub).

DBSCAN PERFORMANCE:
  - geoUtils.dbscan() is O(n²). With hundreds of viewport points it may lag
    during riskAreas computation on low-end devices.

MODEL:
  - Bundled model: landslide_model_package.joblib (scikit-learn, 173 KB).
  - No CatBoost native model currently active (feature_schema.json references
    CatBoost-style categorical handling, but active model may be sklearn).
  - "confidence" field is max(p, 1-p) — not calibrated uncertainty.

SEED:
  - seed.js expects Global_Landslide_Catalog_Export_rows.csv at the path
    terrain-trace/../Global_Landslide_Catalog_Export_rows.csv (one level above).
  - CSV is not committed to the repo.

DEM:
  - himalayan_cop90_dem.tif (1.6 GB) lives at terrain-trace/ root.
  - DEM covers Himalayan region only. Points outside bbox return slope=0.
  - Not committed to git (too large); must be placed manually.

LEGACY ENDPOINTS:
  - /api/predict-point (POST, body: {lat,lng}) — kept for compatibility,
    maps to predictPointLegacy. New clients should use /api/risk/predict.
  - /api/risk-zones (GET) — alias for /api/risk/grid.

─── STARTUP SEQUENCE ────────────────────────────────────────────────────────────

─── CRITICAL RULES FOR FUTURE CHANGES ──────────────────────────────────────────

1. Feature registry is features.json (server/src/config/). To add a feature:
   add entry to features.json, implement provider, add to feature_schema.json.

2. Risk thresholds are in risk-levels.json only — not duplicated in code.

3. All client HTTP goes through src/api/ — never call axios in components.

4. All UI text must come from i18n/en.json — no inline strings.

5. RISK_COLORS/getRiskColor/getRiskClass live in src/types/risk.js — do not
   duplicate color constants in components (they already exist in Map.jsx as
   CORRIDOR_COLORS/AREA_COLORS; keep those in sync with types/risk.js).

6. viewportController and risk.controller both call collectFeatures() — any
   changes to feature aggregation affect both prediction paths.

7. Python service is stateless except for the singleton model. Model swap = file
   replacement in models/active/ + Python service restart.

8. DB failure must not break point prediction (/api/risk/predict works without
   MongoDB). Always guard DB operations with readyState check.

9. scikit-learn version is pinned to 1.9.0 in requirements.txt — do not change
   without re-serializing the model.

10. Viewport point cache is per-point (cacheKey by lat/lng). Clearing it requires
    restarting the Node server (in-memory TtlCache, no Redis).
